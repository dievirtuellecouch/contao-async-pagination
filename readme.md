# Async Pagination

Adds wrapper around paginated frontend modules for asynchronous reloading.

## Configuration

### Scroll to the list after loading (since 5.7.3)

Edit the **Asynchronous pagination** content element and enable **Scroll to the
list after loading**. After successful pagination, the browser scrolls to the
start of that wrapper's reloaded list. Since 5.7.4, selecting or resetting a
filter scrolls to that wrapper's filter controls instead, keeping them visible.
If a custom wrapper has no filter container, the list remains the fallback.
The option is disabled by default and does not scroll on initial page load or
failed requests. Pagination still targets the list when a category is selected.

Scrolling waits for view transitions and respects `prefers-reduced-motion` as
well as existing CSS scroll padding/margins. No additional stylesheet is needed.
Run the Contao database migration after updating to add the checkbox field.
Custom wrapper templates should retain the `data-scroll-to-top` attribute.

Customize the bundle using the `async_pagination` root node.

### Target Frontend Module Types

By default, nested modules of type `list`, `archive` and `reader` can be reloaded. The extension checks if the module type contains one of those keywords, so that all lists and readers (e. g. `newslist` and `faqlist`) are supported out of the box.

To add additional types to your app, use the following setting:

```yaml
async_pagination:
    target_frontend_model_types: ['my_custom_frontend_module_type']
```

#### Shared Max Age

Async responses of the endpoint are cached for 1 hour by default. To change the behaviour, use the following setting. Disable caching by setting the value to `null` or use another number, defined in seconds.

```yaml
async_pagination:
    shared_max_age: 60
```

## Page context (since 5.7.2)

Ajax rendering retains the source page and its language, including Contao's
legacy `$objPage` and default translations. This fixes news category filtering
and pagination in debug mode and keeps pagination labels in the site's language.

The bundled scripts send the optional `_dvc_page` query parameter containing
`window.location.pathname + window.location.search`. Custom clients may send the
same site-local path. Existing endpoint URLs, the `{"html": "..."}` response,
wrapper templates and configuration remain unchanged. Without this parameter,
the endpoint resolves a same-origin `Referer`, then falls back to the site's
published root page. A client without either source cannot identify a specific
child page, so custom clients should pass `_dvc_page` when that matters.

Page context is resolved through Contao routing before its locale, page access
and maintenance listeners. Explicit invalid paths are rejected; foreign URLs
are not accepted as explicit context. Responses based on legacy request headers
vary by `Referer` and `Accept-Language`; protected page responses remain private.

Version 5.7.2 keeps the existing PHP `^8.3` and Contao `^5.7` requirements. It does
not change the supported Contao major/minor versions of 5.7.1.

Since 5.7.3, pagination endpoints are generated by the router, retaining the
preview front controller and installation base path. Source context inherits
preview only from the actual request; Contao continues to enforce preview access.

## Regression tests

With the dependencies from a Contao 5.7 installation available:

```sh
php tests/page-context.php /path/to/contao/vendor/autoload.php
node tests/scroll-to-list.cjs
```

The tests cover German/English context, legacy clients, foreign origins,
invalid paths, custom 404 pages, preview entry points, subdirectories, public
isolation, opt-in scrolling, reduced motion, failed requests and transition timing. Integration verification
should additionally cover news pagination, category filtering and debug mode
with `codefog/contao-news_categories` installed.
